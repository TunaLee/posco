# 요구사항 정의서
사내 비품 신청 시스템을 만든다.
직원이 신청하면 관리자가 승인하거나 반려한다.

## 형식
표로 준다. 열은 기능ID · 기능명 · 상세 설명 · 필수 데이터

## 규칙
- 기능ID 는 영역 3글자 + 번호 2자리로 붙인다
- 상세 설명은 동작 한 문장. 형용사는 쓰지 않는다
| MEM01_01 | 자체 로그인 | 아이디와 비밀번호를 … | REQ01_01 | 비품 신청 | 목록에서 품목과 수량을 …
★
형용사는 쓰지 않는다 한 줄이 편리하게 신청한다 같은 만들 수 없는 문장을 막는다.
→
한 번에 20~30행이 나온다. 사람이 할 일은 빠진 기능을 찾아 채우는 것이다.
✕
나온 표를 그대로 쓰지 않는다. 안 만들 기능까지 섞여 있다.
기준
열 이름을 프롬프트에 박아 두면 다음에 돌려도 같은 모양이 나온다. 문서끼리 이어 붙일 수 있다.

# 와이어프레임
비품을 신청하는 화면. 데스크톱 1280 폭.

## 넣을 것
- 상단: 로고 · 검색창 · 내 정보
- 본문: 품목 목록(사진 · 이름 · 재고) · 수량 입력칸
- 하단: 신청 버튼 하나

## 규칙
색과 실제 이미지는 넣지 않는다. 회색 상자와 선만 쓴다.
★
넣을 것을 위에서 아래 순서로 적는다. 그 순서가 그대로 화면 배치가 된다.
→
폭을 적어야 한다. 안 적으면 휴대폰 화면으로 그려 놓는 경우가 잦다.
✕
색을 지정하면 와이어프레임이 아니라 디자인 시안이 나온다. 고칠 것이 늘어난다.
기준
프롬프트에 못 적는 화면은 아직 정해지지 않은 화면이다. AI 를 부르기 전에 정할 것이 남았다.
