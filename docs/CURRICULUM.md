### 뺀 것 — 커리큘럼 안내

과정 구조를 설명하는 슬라이드를 전부 없앴다. 무엇을 배울지, 지난 회차에 무엇을 했는지는
**강사가 말로 한다.** 슬라이드에 넣으면 아직 안 배운 개념이 앞으로 끌려 나온다.

| 없앤 것 | 이유 |
|---|---|
| Day 1 CH0 챕터 5장 (전체 흐름 · 나흘 동안 하는 일 · 1주차와 2주차의 경계 · AI가 하는 일 · 에러 없이 돌아가는 오답) | 첫 시간에 `groupby`·회귀·LLM이 이름부터 나온다. 배울 준비가 안 된 청중에게 소음이다 |
| Day 4 나흘 정리 · 2주차 로드맵 2장 | 전체 회고와 다음 주 예고. Day 4 내용만 남긴 정리 한 장으로 대체했다 |

## 데이터셋

**합성 이차전지 양극재 소성 공정 데이터** 1412행 11열. 나흘 내내 같은 표를 쓴다.
실제 데이터가 아니라 [`data/make_dataset.py`](../data/make_dataset.py)가 난수에서 만든 것이고,
시드가 고정돼 있어 언제 돌려도 같은 파일이 나온다. 회사·설비·제품을 특정하지 않는다.

```python
url = 'https://tunalee.github.io/posco/data/batch_quality.csv'
df = pd.read_csv(url, thousands=',', na_values=['N/A', '-'])   # 열 이름은 한글
```

열 정의와 심어 둔 문제는 [docs/data/README.md](data/README.md)에 있다.

가르칠 것을 일부러 심어 뒀다.

- **결측** — `입도` 112건, `수분율` 73건. 표기가 `N/A` `-` `''`로 흔들린다
- **타입 사고** — `불순물`가 `'1,240'` 쉼표 탓에 `object`로 읽힌다. `.max()`가 `'998'`을 낸다
- **표기 흔들림** — 같은 설비가 `'A'` `'a'` `' A '`로 24종이 된다
- **이상치** — `성형압력`의 센서 오류값 `999.0` 18건
- **중복** — 같은 배치가 두 번 기록된 12행
- **불균형** — 불량 18.8%. 전부 양품이라 찍으면 정확도 81%가 나온다
- **무관한 열** — `성형압력`는 용량과 상관 −0.05다

`방전용량`가 회귀 정답, `양품여부`가 분류 정답이다. 온도는 890 °C 부근이 최적이고
대부분의 배치가 그 아래에 있어, **선형 모델도 어느 정도 맞히고 트리 계열이 더 잘 맞힌다.**

| 모델 | 분류 정확도 |  | 회귀 | R² |
|---|---|---|---|---|
| 전부 양품이라 찍기 | 0.810 | | 선형 회귀 | 0.719 |
| 로지스틱 회귀 | 0.896 | | 랜덤 포레스트 | 0.837 |
| 결정 트리 | 0.922 | | | |
| 랜덤 포레스트 | 0.944 | | | |

`line_master.csv`(6행)를 `merge`하면 **설비가 오래될수록 불량률이 높다**는 것이 드러난다 —
2015년 설비 21.4%, 2021년 16.0%.

Day 3의 평가 지표 전체(혼동 행렬 · 정확도의 함정 · 정밀도/재현율 · 지표 선택)가
불량 검출 위에서 돈다. 놓친 불량은 고객 클레임, 헛경보는 라인 정지 — 비용이
비대칭이라 지표 선택을 설명하기에 맞다.

**회사명은 넣지 않는다.** 공개 저장소이므로 업종 일반 용어만 쓴다.

### 그래프는 먼저 설명하고 들어간다

GraphRAG 는 넣되 **그래프 자체를 모르는 상태를 전제**한다. 점과 선으로 무엇을 적는지부터
시작한다.

```
그래프란       점(설비·공정·불량)과 선(관계)으로 적는 방식 · 표와 무엇이 다른가
표로 안 되는 것  "이 부품이 쓰이는 공정을 따라가면 어디까지 이어지나"
지식 그래프     문서에서 개체와 관계를 뽑아 점과 선으로 만든다
GraphRAG      벡터 검색은 비슷한 조각을 찾고, 그래프는 이어진 것을 따라간다
언제 값이 있나  연결을 묻는 질문 · 한 문단 안에 답이 없고 여러 문서에 흩어진 것
```

### 8/13 은 만드는 법이 아니라 시키는 법이다

수강생에게 **Codex 계정이 있다.** 에이전트를 처음부터 만들 이유가 없고, 만들 줄 알아도
직무에서 쓸 일이 드물다. 그러니 개념은 개념대로 배우되 **실습은 Codex 로 시켜 보는 것**으로
간다.

방법은 2주차 D4 에서 쓴 것을 그대로 옮긴다 — **같은 일을 다르게 시켜 견준다.**

| 견줄 것 | 한쪽 | 다른 쪽 | 배우는 개념 |
|---|---|---|---|
| 맥락 | 그냥 시킨다 | `AGENTS.md` 를 두고 시킨다 | 컨텍스트 엔지니어링 |
| 쪼개기 | "만들어 줘" 한 줄 | 계획 → 실행 → 검증 세 번으로 | 작업 분해 |
| 지목 | 파일을 안 알려 준다 | 고칠 파일을 지목한다 | 참조와 탐색 비용 |
| 검증 | 그냥 끝낸다 | 테스트를 먼저 쓰게 한다 | 검증 루프 |
| 도구 | 도구 없이 묻는다 | MCP 로 붙여 준다 | 도구 호출 |

다섯 줄 모두 **개념 하나에 실험 하나**로 짝지어져 있다. MCP·하네스·컨텍스트를 말로만
배우지 않고 그 자리에서 효과를 본다.

**이 날의 수치는 강사가 현장에서 뽑는다.** 에이전트 출력은 돌릴 때마다 달라져 미리 재
둔 값을 실을 수 없다. 덱에는 **무엇을 견줄지와 무엇을 볼지**만 싣고, 결과는 그 자리에서
채운다. 다른 날 덱과 다른 점이므로 슬라이드에 그렇게 밝힌다.

**정답이 정해지지 않은 영역**을 다루는 법은 하루를 따로 주지 않는다. 마지막 내용일의

D3 의 「가려서 재 본다」, D4 의 「형식은 잡히고 판단은 안 잡힌다」가 그 준비다.

세 방식을 **훈련 5,000장 · 테스트 1,000장** 같은 조건으로 재서 하루의 줄기로 삼는다.

| 방식 | 학습할 계수 | 정확도 | 1,000장 중 오답 |
|---|---|---|---|
| 펴서 `Linear` | 394,634 | 0.3350 | 665장 |
| CNN 처음부터 | 60,362 | 0.4790 | 521장 |
| resnet18 특징 + `Linear` | 5,130 | 0.8530 | 147장 |

계수는 **77분의 1**로 줄어드는데 정확도는 **2.5배**가 된다. 5만 장으로 늘리면
펴서 `Linear` 0.4470(12초) · CNN 0.6843(127초)다.

전이학습은 훈련 장수를 줄여도 버틴다 — 5,000장 0.8530 · 2,000장 0.8440 ·
500장 0.7840 · 200장 0.7230. **같은 200장으로 CNN 을 처음부터 학습시키면 0.2990** 이다.
`Normalize` 를 빼면 0.8530 이 0.7430 으로 떨어진다 — 에러는 나지 않아 숫자로만 알 수 있다.

풀링은 **빼 보고 재서** 실었다. 같은 구조에서 풀링만 빼면 계수가 60,362 에서 674,762 로
11배가 되고 학습이 10초에서 24초로 늘지만 **정확도는 0.4580 에서 0.5250 으로 오른다**.
32×32 짜리 작은 사진이라 감당된 것이라, 풀링은 정확도가 아니라 **크기를 감당하는 장치**라고
맺는다. 224×224 면 마지막 `Linear` 계수만 2,007,050 대 32,112,650 이다.

슬라이드의 모든 수치는 `notebooks/day5_solution.ipynb` 를 그대로 돌려 나오는 값이다.
모델을 만들 때마다 `torch.manual_seed(42)` 를 먼저 불러 **어느 벌에서 돌려도 같은 값**이 나온다.

새로 배우는 API 는 다섯 줄뿐이다 — `nn.Conv2d` · `nn.MaxPool2d` ·
`models.resnet18` · `requires_grad = False` · `net.fc` 대입.
`Flatten` · `Linear` · `ReLU` · `Adam` · 학습 루프는 1주차 것을 그대로 쓴다.

모든 수치는 **Qwen2.5-1.5B-Instruct 를 로컬에서 열어** 뽑았다. 계수 15억 · 층 28 ·
어텐션 머리 12 · 어휘 151,665 · 문맥 32,768.

같은 모델에 **앞부분만 바꿔 넣은** 결과가 이 덱의 줄기다.

| 앞에 둔 것 | 이어 쓴 것 |
|---|---|
| `이 제품 정말 좋아요.` | 편안하고, 깔끔한 느낌이 좋았어요. |
| 지시문 + `답:` | **칭찬** |
| 예시 3줄 (`사과 → apple` …) | **grape** |
| `프랑스의 수도는` | 루이즈로, 이곳에서 178… (틀림) |
| `질문: …? 답:` | 프랑스의 수도는 파리입니다. |
| `…도시 이름만 한 단어로` | 파리 |

어텐션은 **14층 0번 머리**를 통제 실험 5개로 검증해 실었다. `철수는 → 사과 0.476`,
`영희는 → 포도 0.667`, 순서를 바꿔도 `사과 0.749`. **뜻 없는 낱말**에서도
`가나는 → 다라 0.627`, `마바는 → 사아 0.751` — 의미가 아니라 무늬로 작동한다.
이것이 few-shot 이 듣는 기계적 이유이고, CH2 와 CH3 를 잇는 다리다.

처음 고른 머리(11층 13머리)는 `그는 → 철수 1.000` 으로 대명사 해소처럼 보였으나,
문장을 "바나나가 창문에게…"로 바꿔도 첫 어절에 1.000 이 갔다. **첫 토큰에 몰리는 현상**이라
쓰지 않았다. 336개 머리를 전부 뒤져 통제 5개를 모두 통과한 것만 실었다.

프롬프트로 **안 되는 것**도 측정해 실었다. `17 x 24` 는 308(정답 408), 없는 장비
`XR-7000` 의 최대 온도를 125도라고 답한다. 네 칸 틀을 채우면 JSON 형식은 완벽히
나오지만 845도·815도·770도를 **모두 정상**이라 판정하고 "800~830 사이에 있다"는
거짓 이유까지 붙인다. 형식이 맞아서 더 위험하다는 것이 CH4 의 결론이다.

```

  CH0 데이터를 갖추기   폴더가 곧 라벨 · 훈련과 검증을 나눈다 · 크기가 제각각 · 첫 결과 0.9608

  CH2 한쪽이 적은 데이터 한 종류를 줄이면 · 종류별로 재는 코드 · 대응하는 세 가지 손

사진 **397장**(훈련 244 · 검증 153)으로 한다. 현장에서 모을 수 있는 양에 맞춘 것이다.
`ImageFolder` 를 쓰므로 **폴더 이름을 `정상`·`불량` 으로 바꾸면 코드 변경 없이** 현장 문제가 된다.

이 덱은 만드는 법보다 **나온 숫자를 믿어도 되는지**에 절반을 쓴다.
검증이 153장이라 **한 장이 0.65%** 이고, 모든 비교에 차이를 사진 장수로 환산해 싣는다.

| 재 본 것 | 결과 |
|---|---|
| 244장 전이학습 | 0.9608 (학습한 계수 1,026개) |
| 훈련 사진 244 → 120 → 60 → 30장 | 0.9608 · 0.9542 · 0.9477 · 0.9150 |
| 난수 씨앗 10번 | 열 번 모두 0.9608 (폭 0.0000) |
| 어느 30장을 뽑는가 | 0.9216 ~ 0.9346 (폭 사진 2장) |
| 라벨 오염 5·10·20·35% (각 3회) | 0.9259 · 0.8932 · 0.8301 · 0.7298 |
| 개미 123 → 40 → 12장 | 전체 0.9608 · 0.9346 · 0.7778 |
| 문턱 0.3 → 0.9 | 재현율 0.964 → 0.783, 정밀도 0.976 → 0.985 |

**흔들림의 원인은 학습이 아니라 데이터다.** 씨앗을 열 번 바꿔도 값이 똑같은데,
어느 사진을 뽑느냐를 바꾸면 흔들린다. **틀린 라벨 한 장이 검증 오답을 약 0.4장 늘린다** —
12장만 잘못 붙어도 사진을 244장에서 30장으로 줄인 것과 비슷한 손해다.

**전체 정확도가 실패를 가린다.** 개미 12장 : 벌 121장이면 전체 0.7778 인데 뜯어 보면
벌 1.0000 · 개미 0.5143 이다. 웬만하면 벌이라 답하는 모델이 된 것이다.

증강은 **이 데이터에서 듣지 않았다**. 얼림/풀기 × 증강 유무 네 조합이 0.9346~0.9477 로
전부 사진 두 장 안에 모인다. 계수를 1,026개에서 8,394,754개로 늘려도 그렇다.
이유도 측정했다 — 검증 사진을 **좌우로 뒤집으면 한 장도 더 안 틀리는데**(0.9608 그대로)
**흐리게 하면 15장**을 더 틀린다(0.8627). 이미 강한 변형을 늘려 봐야 새로 알려 준 것이 없다.
그래서 증강은 목록을 베끼지 말고 **약한 쪽을 먼저 재서** 고르라고 맺는다.

```
2주차 D3  이미지 처리 모듈 개발 — day6 에서 만든 그 분류기(0.9608)를 그대로 열어 본다
  CH0 근거가 필요한 이유  확신 0.996 으로 틀린 사진 · 정확도가 가리는 것
  CH1 히트맵 만들기      마지막 합성곱 층의 7x7 · 기울기로 재는 무게 · 갈고리 코드 ·
                        맞힌 사진의 히트맵
  CH2 틀린 것을 열어 보기 마른 잎을 본 벌 · 흰 꽃을 본 개미 · 배경이 근거로 쓰이는가
  CH3 히트맵을 믿는 법    가려서 검증하기 · 한계
  CH4 현장에 쓰기        검수 흐름 · 실습 · 사흘 정리
```

**Grad-CAM 을 그림으로만 보이지 않고 검증까지 했다.** 가린 넓이를 20%로 고정하고
어디를 가리는지만 바꿔 재면 이렇게 갈린다.

| 가린 곳 | 넓이 | 정확도 | 더 틀린 사진 |
|---|---|---|---|
| 그대로 | — | 0.9608 | — |
| 히트맵이 가장 붉은 20% | 20% | 0.7843 | **27장** |
| 아무 데나 20% | 20% | 0.8693 | 14장 |
| 히트맵이 가장 파란 20% | 20% | 0.9608 | **0장** |

히트맵이 중요하다고 한 곳을 가리면 무작위보다 두 배 무너지고, 안 중요하다고 한 곳은
5분의 1을 지워도 한 장도 안 틀린다. **그림이 단서고 이 표가 증거다**라고 맺는다.

오답 두 장이 교재의 중심이다. **마른 잎 위의 벌**은 히트맵이 잎을 덮고 개미라 답했고
(확신 0.996), **흰 꽃 위의 개미**는 꽃을 보고 벌이라 답했다(0.985). 둘을 합치면
이 모델이 **땅이면 개미, 꽃이면 벌**이라고도 배웠음이 드러난다.

배경을 근거로 쓴다는 것은 따로 쟀다. 가운데 절반을 검게 하면 16장, **가장자리만 검게 해도
13장**을 더 틀린다. 대상을 지운 것과 배경을 지운 것의 손해가 비슷하다.

히트맵 그림 여덟 장(원본 4 · 히트맵 4)을 덱에 직접 담아 파일이 1.05MB 다.

## 특강 · AI 도구로 웹 서비스 만들기

4일 과정과 별개로 도는 **반나절(3~4시간)** 덱. 코드를 직접 쓰지 않고, 무엇을 만들지 정하고
무엇으로 만들지 고르는 데까지 간다. 4일 과정의 데이터셋과 무관하다.

```
CH0 방법론 고르기      네 가지 방법 · 룰베이스 · 머신러닝 · 딥러닝 · AI 에이전트 · 고르는 네 질문
CH1 만들기 전에 적는 것  기획서 목차(여덟 항목) · 마크다운 · 프롬프트 세 칸 ·
                       요구사항 정의서 → 프롬프트 · 기능 ID ·
                       흐름도 도형 · 로그인 흐름도 → 프롬프트 ·
                       와이어프레임 → 프롬프트 · 만드는 순서 · 간트차트 → 프롬프트

                       AI 도구 네 단계 · 에이전트 명세서 · 배포 순서 · 정리

기획서는 여덟 항목이고, 그중 **1~4는 사람이 정하고 5~8은 AI 가 초안을 낸다**.
5~8 네 문서마다 **AI 에게 그대로 붙여 넣는 프롬프트**를 한 장씩 붙였다. 모두 같은 세 칸
(`무엇을 만드는가` · `## 형식` · `## 규칙`)을 쓰고, 예시 서비스는 사내 비품 신청 시스템 하나로 관통한다.

Day 4 실습은 손글씨 숫자(MNIST)로 배우고 **동물 사진(CIFAR-10)으로 확인한다.**
같은 모델에 입력 칸 수만 바꿔 대 보면 0.963 이 0.428 로 떨어지고, 은닉을 네 배로
키워도 0.436 에 그친다 — 펴서 넣는 방식의 한계를 손으로 만져 보는 자리다.
