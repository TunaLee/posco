CH0문제

버전 충돌

같은 곳에 다른 버전을 깔아 본다
$ pip install numpy==1.26.4
$ python -c "import numpy; print(numpy.__version__)"
1.26.4

$ pip install numpy==2.5.2        ← 다른 버전을 깐다
$ python -c "import numpy; print(numpy.__version__)"
2.5.2                             ← 앞의 것이 사라졌다
제일 먼저 만나는 벽
프로젝트가 둘인데 필요한 버전이 다르면 한쪽을 포기해야 한다.
/
CH0가상환경

가상환경

나누지 않으면

라이브러리가 컴퓨터 한 곳에 쌓인다.

프로젝트 A 와 B 가 같은 곳을 쓴다.
버전이 다르면 나중에 깐 것이 이긴다.

한쪽이 안 돈다

가상환경을 쓰면

프로젝트마다 자기 폴더를 하나 갖는다.

그 안에만 라이브러리를 깐다.
A 와 B 가 서로를 안 건드린다.

둘 다 돈다
한 줄로
가상환경은 프로젝트마다 따로 두는 라이브러리 폴더다. 그게 전부다.
/
CH0가상환경

가상환경이 필요한 이유

→
프로젝트가 하나면 없어도 된다. 컴퓨터 한 곳에 깔고 쓰면 그만이다.
→
둘이 되는 순간 부딪힌다. 같은 라이브러리를 다른 버전으로 쓰는 일이 흔하다.
→
남이 만든 것을 받아 볼 때도 그렇다. 내려받은 것이 내 것을 망가뜨리면 안 된다.
★
지우기도 쉽다. 폴더 하나만 버리면 깔았던 것이 다 사라진다.
바꿔 말하면
프로젝트를 서로 모르게 만드는 일이다.
/

CH0가상환경

venv 와 conda

환경을 둘로 만들어 각각 깐다
$ python -m venv A  &&  A/bin/pip install numpy==2.5.2
$ python -m venv B  &&  B/bin/pip install numpy==1.26.4

$ A/bin/python -c "import numpy; print(numpy.__version__)"
2.5.2
$ B/bin/python -c "import numpy; print(numpy.__version__)"
1.26.4                            ← 둘이 같이 산다
conda 로 하던 것
conda create -n 이름 도 같은 일을 한다. 도구만 다르다.

CH4읽기

Dockerfile 읽기

Dockerfile
FROM python:3.12-slim      바탕
WORKDIR /app               작업 폴더
COPY requirements.txt .    목록을 넣고
RUN pip install -r requirements.txt   만들 때 한 번 돈다
COPY app.py .              코드를 넣고
EXPOSE 8000                연다고 적어 둔다
CMD ["python", "app.py"]   뜰 때 돈다
둘만 구분하면 된다

CH91단계

폴더 구조

이 모양으로 맞춰 둔다
공정도우미/
├─ compose.yml            ← 셋을 묶는 파일
├─ .env                   ← 키. 커밋 안 한다
├─ web/                   ← Next.js 화면
│   ├─ package.json
│   └─ app/
└─ api/                   ← 파이썬 서버
    ├─ requirements.txt
    └─ app.py
먼저 이걸 맞춘다
폴더가 섞여 있으면 Codex 도 헷갈린다. 앱마다 폴더 하나로 갈라 둔다.
/
CH92단계

Dockerfile 프롬프트

앱마다 한 번씩 시킨다
web/ 폴더에 Dockerfile 을 만들어 줘. Next.js 앱이다.

  node 22-alpine 을 쓴다
  만드는 단계와 돌리는 단계를 나눈다 (standalone 출력)
  3000 포트를 연다. HOSTNAME 은 0.0.0.0 으로 준다
  .dockerignore 도 만든다 — node_modules 와 .next 를 넣는다
  파일은 .jsx 로 쓴다. TypeScript 는 안 쓴다
마지막 두 줄이 있어야
node_modules 를 안 빼면 맥용 파일이 이미지에 들어가 리눅스에서 깨진다.
/
CH92단계

받은 것 확인

web/Dockerfile
FROM node:22-alpine AS build          만드는 단계
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine                  돌리는 단계
ENV HOSTNAME=0.0.0.0 PORT=3000       ← 이 줄이 있나 먼저 본다
COPY --from=build /app/.next/standalone ./
CMD ["node", "server.js"]
세 곳을 확인한다
0.0.0.0 이 있나 · 키를 ENV 로 박지 않았나 · 데이터를 COPY 하지 않았나.

CH93단계

compose 프롬프트

셋을 묶는다
compose.yml 을 만들어 줘. 서비스는 둘이다.

  web  ./web 을 빌드한다. 3000 포트를 밖으로 연다
  api  ./api 를 빌드한다. 8000 포트를 밖으로 연다
       web 은 api 를 http://api:8000 으로 부른다

  키는 .env 에서 읽는다. 값은 파일에 적지 마라
  데이터는 볼륨에 남긴다
IP 를 적지 않는다
http://api:8000 — 서비스 이름이 곧 주소다. compose 가 이어 준다.
/

CH9주의

폐쇄망 준비

고칠 것왜
build: 를 image: 로build 로 두면 받는 쪽이 다시 만들려고 인터넷을 찾는다
--platform linux/amd64맥에서 만든 것은 arm64 다. x86 서버에서 안 뜬다
Docker Desktop 라이선스규모가 있는 회사는 유료다. 담당자에게 먼저 확인한다
★
첫 줄이 제일 많이 걸린다. 폐쇄망용 compose.yml 은 따로 둔다.
만들 때 정한다
옮길 곳이 x86 이면 처음부터 --platform linux/amd64 로 만든다.

CH10정리

오늘 배운 여섯

1
이미지는 놓여 있고 컨테이너는 돌고 있다. build 로 만들고 run 으로 띄운다.
2
Dockerfile 은 Codex 가 쓴다. 여섯 칸을 알려주고 나온 것을 읽는 것이 사람 몫이다.
3
상자 안에 둔 것은 지우면 사라진다. 남길 것은 볼륨이나 물린 폴더에 둔다.
4
앱은 0.0.0.0 으로 열어야 밖에서 붙는다. 안 붙으면 여기부터 본다.
5
키는 띄울 때 준다. 이미지에 넣으면 지워도 남는다.
여섯
compose 는 여러 상자를 이름으로 이어 한 줄로 올리고 내린다.
/
CH10오개념

오개념 다섯

흔한 생각실제
컨테이너는 가상 머신이다운영체제를 따로 안 띄운다. 그래서 가볍고 빠르다
재시작하면 데이터가 사라진다재시작은 괜찮다. rm 할 때 사라진다
-p 를 열면 무조건 붙는다앱이 127.0.0.1 로 열면 안 붙는다
이미지를 지우면 키도 지워진다받아 간 사람 이미지에는 그대로 남아 있다
빌드가 되면 맞게 만든 것이다빌드는 문법만 본다. 도는지는 별개다
제일 많이 데이는 것
빌드가 됐으니 맞겠지 — 반드시 띄워서 불러 본다.
/
CH10요약

치트시트

자주 쓰는 것
docker run -d --name 이름 -p 앞:뒤 이미지     띄운다
docker ps                                   무엇이 도나
docker logs 이름 --tail 20                  왜 안 되나
docker exec 이름 ls /경로                   안을 본다
docker stop / start / rm -f 이름            멈춤 · 켬 · 없앰
docker build -t 이름:버전 .                 만든다
docker compose up -d --build / down         묶음으로 올림 · 내림
막히면 둘
docker ps 로 떴는지, docker logs 로 왜인지.
