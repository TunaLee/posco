안 풀린 것어제 노트북에서 어땠나

CH1정의

한 문장으로 줄인 MCP

Model Context Protocol

LLM 앱이 외부 데이터와 도구를 한 가지 방식으로 쓰게 하는 규약. 2024년 11월에 공개돼 사실상 표준이 됐다.

어제 만든 함수 하나를 서버로 내보내면
서버 하나   defect_rate(machine, shift)

Claude Code   「3호기 야간 불량률」  → 이 함수를 부른다
사내 챗봇      「3호기 야간 불량률」  → 같은 함수를 부른다
Codex         「3호기 야간 불량률」  → 같은 함수를 부른다

앱마다 다시 짜지 않는다. 고칠 때도 한 곳만 고친다
양쪽 다
도구는 한 번 서버로 만들면 되고, 앱은 한 번 클라이언트만 만들면 된다.

CH1통신

JSON-RPC 위에 얹힌 규약

클라이언트 → 서버
{"jsonrpc": "2.0", "id": 3, "method": "tools/call",
 "params": {"name": "defect_rate",
            "arguments": {"machine": "3호기", "shift": "야간"}}}
서버 → 클라이언트
{"jsonrpc": "2.0", "id": 3,

몰라도 된다
이 배선은 FastMCP 가 숨긴다. 데코레이터를 단 함수가 그대로 이 메시지가 된다.
/
CH1메시지

오가는 메시지 네 가지

Request

요청

id가 붙고 응답을 기대한다. 예: 도구 목록·도구 호출.

Response

응답

결과(result) 또는 오류(error)를 돌려준다.

Notification

알림

id 없이 한 방향 통지. 응답이 없다. 예: 진행 상황.

오류도 규격이 있다

오류는 코드+메시지로 표준화된다. 참고로 2025-06 스펙에서 여러 요청을 묶는 배치(batching)는 제거됐다.

/
CH2세 기둥

서버가 내주는 셋

행동

Tools

POST 같은 호출 함수. 부작용 있음 — 메일 전송, DB 쓰기, 계산.

데이터

Resources

GET 같은 읽기 전용 데이터. URI로 주소 지정 — 문서·설정·로그.

템플릿

Prompts

재사용 프롬프트 템플릿. 호스트에서 슬래시 명령처럼 노출.

기억
셋 다 만들어 본다. 그중 Resource 는 뒤에서 더 깊게 설계한다.
/
CH2호출과 결과

불렀을 때 돌아오는 것

종류클라이언트 호출결과
Tool
행동·계산		call_tool("add", {a:2, b:3})5
Resource
읽기 데이터		read_resource("config://status"){"version":"1.0","env":"dev"}
Prompt
메시지 템플릿		get_prompt("code_review", {...})"다음 python 코드를 리뷰… print(1)"
핵심
Tool은 행동의 결과값, Resource는 URI로 읽은 데이터, Prompt는 채워진 메시지 — 부르는 함수도 셋 다 다르다(call_tool / read_resource / get_prompt).
/
CH2Tool vs Resource

읽기와 행동

Tool (행동/POST)

상태를 바꾸거나 외부에 영향. “티켓 생성”, “이메일 발송”, “주문”.

Resource (읽기/GET)

그냥 읽어오기. “정책 문서 읽기”, “설정값 조회”, “로그 보기”.

한 줄 규칙
부작용 있으면 Tool, 읽기 전용이면 Resource.

CH2미니 실습

Tool 과 Resource 가르기

과제 — 각 기능을 Tool / Resource로 분류

A
“오늘 환율 조회해 반환”
B
“회의록을 캘린더에 일정으로 등록”
C
“사내 휴가 정책 문서 읽기”
D
“두 수를 더한 결과 반환”

정답

C = Resource(읽기) / A·B·D = Tool(조회 호출·등록·계산처럼 ‘행위’). 외부 상태를 바꾸는 B는 분명한 Tool.

@mcp.tool
async def send(msg: str, ctx: Context) -> str:
    r = await ctx.elicit("어느 계정으로?",
                       response_type=Account)
    if r.action != "accept": return "취소됨"
    ...   # r.data 로 진행
감각
Tool은 한 번 부르고 끝이 아니라, 필요하면 사용자·모델과 주고받는다. 지우기·결제처럼 되돌릴 수 없는 일에 건다.

최소 권한

입력 검증

모델이 보내는 인자를 믿지 말고 검증. 경로·쿼리 주입 방지.

비밀 보호

API 키·토큰은 코드·로그에 노출 금지. 환경변수로.

원칙
도구는 ‘작고 명확하게’ — 하나의 도구가 한 가지 일을, 설명을 분명하게(모델이 오용하지 않도록).

async def run_query(sql: str, ctx: Context) -> list:
    if not sql.strip().lower().startswith("select"):
        raise ValueError("SELECT 문만 허용")   # 최소권한·검증
    await ctx.info(f"실행: {sql[:40]}")        # 감사 로그
