CH0경계

모델과 하네스의 경계

모델이 하는 일

글을 읽고 다음에 무엇을 할지 고른다.

말할 줄 안다 · 코드를 쓸 줄 안다
파일을 직접 열지는 못한다

하네스가 하는 일

고른 것을 실제로 실행하고 결과를 돌려준다.

파일을 열어 준다 · 명령을 돌려 준다
못 할 일을 막고 · 규칙을 앞에 붙인다

바꿀 수 있는 쪽
모델은 고르는 데까지다. 나머지는 전부 하네스가 하고, 그쪽은 고칠 수 있다.
/
CH0역할

하네스가 맡는 네 가지

1
도구 — 파일 읽기 · 명령 실행 · 검색 · 브라우저를 쥐여 준다. 없으면 말만 한다.
2
순서 — 무엇을 먼저 하고 언제 멈출지 정한다. 계획 → 실행 → 검증 같은 흐름이다.
3
울타리 — 지우면 안 될 것을 막고, 위험한 명령은 사람에게 물어본다.
4
배경 — 프로젝트 규칙 · 코딩 관례 · 자주 쓰는 절차를 매번 안 적어도 들어가게 한다.
오늘 손대는 곳
넷 다 설정 파일과 문서로 바꾼다. 모델을 바꾸는 것이 아니다.

지휘자를 두는 방식

1
쪼갠다
큰 요청을 겹치지 않는 조각으로 나눈다
2
나눠 준다
조각마다 서브에이전트를 하나씩 띄운다
3

보고가 다 올 때까지 기다린다
4
합친다
겹치는 결론을 하나로 묶고 어긋난 것을 가려낸다
5
검사한다
합친 결과를 다시 한 번 돌려 본다
한 줄로 시키면 안쪽에서 이렇게 나뉜다
> 설비 화면 세 개를 만들어 줘

● Task(목록 화면)      ● Task(상세 화면)      ● Task(설정 화면)
  ↳ 끝                 ↳ 끝                 ↳ 끝

● Read(3개 결과 비교)                 ← 여기서 합친다
● Bash(npm run build)                 ← 합친 뒤 한 번 돌린다
4단계가 제일 어렵다
쪼개기는 쉽다. 합치기에서 대부분 깨진다. 그래서 조각을 겹치지 않게 자른다.

비밀번호가 들어간 명령은 허용 목록에 넣지 않는다. 환경 변수로 빼고 명령에서 지운다.

가장 잦은 사고
허용 목록에 접속 정보가 섞여 공개 저장소로 올라간다. 넣기 전에 한 번 읽어 본다.

1
운영 데이터베이스 접속 — 읽기라도 막는다. 개인 정보가 창에 통째로 들어온다.
2
비밀 파일 읽기 — .env · 키 파일 · 인증서. 한 번 들어가면 대화 기록에 남는다.
3
되돌릴 수 없는 명령 — rm -rf · git push --force · 테이블 지우기.
4
바깥으로 보내기 — 사내 코드를 외부 서비스에 올리는 명령을 막는다.
5
결재 없는 배포 — 운영에 올리는 명령은 사람 손을 반드시 거치게 한다.
막는 방법 두 가지
금지 목록에 적거나 도구를 아예 빼는 것이다. 둘 다 파일로 한다.

CH6실습

금지 목록 만들기

.claude/settings.json — 저장소에 같이 넣는다
{
  "permissions": {
    "deny": [
      "Read(./.env*)",                 ← 비밀 파일
      "Bash(rm -rf:*)",
      "Bash(git push --force:*)",
      "Bash(psql:*)"                   ← DB 직접 접속
    ]
  }
}

CH8도입

들이는 순서

1
한 팀에서 쓴다
규칙 파일 한 장부터 만들어 두 주 써 본다
2
막는 장치를 건다
금지 목록과 훅을 저장소에 넣는다
3
반복을 스킬로 뺀다
세 번 넘게 설명한 절차를 문서로 굳힌다
4
묶어서 나눈다
스킬 묶음을 사내 저장소에 올려 다른 팀이 받게 한다
5
규격을 맞춘다
AGENTS.md 와 MCP 로 통일해 도구를 바꿔도 남게 한다
단계걸리는 기간끝난 표시
한 팀에서 쓴다두 주규칙 파일이 저장소에 있다
막는 장치를 건다한 주.env 읽기가 실제로 막힌다
반복을 스킬로 뺀다계속세 번 넘게 설명한 것이 없다
묶어서 나눈다한 달다른 팀이 받아 쓴다
1단계를 건너뛰지 않는다
한 팀이 두 주 써 보기 전에 전사로 펴면 반드시 되돌린다.

제일 크게 줄이는 한 가지

CH8정리

오늘의 한 문장

1
모델은 고를 뿐이다 — 나머지는 전부 하네스가 하고, 그쪽은 파일로 고칠 수 있다.
2
항상 필요하면 규칙 파일 — 가끔 필요하면 스킬. 읽을 것이 많으면 서브에이전트.
3
막을 때는 도구를 뺀다 — 말로 부탁하지 않는다. 금지 목록과 훅으로 건다.
4
겹치면 안 나눈다 — 고칠 파일이 겹치는지 먼저 본다. 그래도 나눠야 하면 폴더를 가른다.
5
규격을 맞춰 둔다 — MCP 와 AGENTS.md 가 같으면 갈아타도 다시 안 만든다.
가장 값싼 개선
더 좋은 모델을 기다리는 것보다 규칙 파일 한 장이 빠르다.
